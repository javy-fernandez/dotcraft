# Batch 2: HTTP Client and endpoint workflows

This slice builds on the upstream HTTP Client and endpoint scanner already delivered in the combined integration branch (`335d53d`, whose tree matches published `6cabba5`). It adds five usable, bounded workflows. The implementations are original Rust/egui work; no third-party code or assets were copied. OpenAPI interpretation follows the [OpenAPI 3.1.1 specification](https://spec.openapis.org/oas/v3.1.1.html) within the subset below.

| Feature | Delivered and tested scope | Remaining limitations |
| --- | --- | --- |
| J-05 | The existing HTTP Client exposes Cancel Request; replacing a request, closing a workspace, or dropping the client aborts its task and closes an active connection. A completed, cancelled worker cannot replace the current result. Responses stop at 8 MiB. | A blocking regular-file read already in progress finishes in its worker; cancellation prevents the resolved request from being sent. No request history, collections, or scripted assertions. |
| J-06 | The environment selector discovers names asynchronously, caches them per active `.http`/`.rest` file, and has Refresh environments. Refresh retains valid selections and clears removed selections; switching files clears the previous selection. Environment and file-body resolution execute off the UI thread. Existing public/private/Visual Studio user environments, `$shared`, dynamic variables and relative body files remain supported. | No environment-file editor or watcher. Malformed/missing environment files retain upstream behavior and do not add names. File changes require explicit refresh. |
| J-09 | The Endpoints window searches method, route, handler and file using case-insensitive AND terms, filters by method, groups by project and optionally by method, and retains handler navigation/request generation. Scans and request-file generation run in workers with cancellation. | This uses the existing source scanner, not runtime endpoint metadata. Results are capped and do not establish Razor Pages or full ASP.NET discovery parity. |
| J-12 | The window counts potential route conflicts, filters to affected endpoints, and shows the other handler and source location. Analysis compares compatible HTTP methods (including ANY), case-insensitive literal routes and parameter-name-independent route shapes while retaining constraints. | Warnings are per project and conservative source hints. Custom constraints, runtime conventions, route order/precedence, optional-route expansion and cross-project hosting are not evaluated. |
| J-24 | Expand Import OpenAPI JSON in Endpoints, enter an explicit local input path and a new `.http`/`.rest` output path, then click Import requests. The worker produces editable templates and opens the new file. Existing files are never overwritten and requests are never automatically sent. | JSON OpenAPI 3.0/3.1 only; requires an explicit absolute HTTP(S) server. No YAML, reference resolution, authentication import, schema-driven example generation, cookies, arrays/object parameters or non-JSON request bodies. Unsupported parameter serialization and referenced path items/parameters/request bodies produce errors. |

## OpenAPI template behavior

The importer supports GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS and TRACE. It honors operation/path/document server precedence, server-variable defaults, and operation parameter overrides. Inline scalar path/query/header examples and JSON body examples are preserved. Query/path examples are percent encoded. Missing scalar examples use `1` or `value`; a JSON body without an inline example uses `{}`. Generated comments identify these placeholders and the omitted authentication/schema behavior. Unused component and response schemas are not fetched or interpreted. External references are never downloaded.

Input is limited to 2 MiB and 512 operations; generated files to 4 MiB. Parameter sets are limited to 256 entries per owner, examples to 2048 bytes, and generated routes to 64 KiB. Invalid/injected headers, unsupported servers and unresolved route parameters fail before writing. Cancellation is checked before creating the output; a bounded write that has already started may finish and leave the new file, while its completion notification is discarded. Cancelling request generation similarly cannot roll back a write already started. Its token is checked again immediately before writing; a cancelled operation keeps its busy slot until worker acknowledgement, preventing replacement writers from racing the same file.

## Resource and lifecycle boundaries

HTTP source input is limited to 1 MiB, each environment file to 1 MiB, file bodies and the variable-expansion budget (processed input plus terminal/dynamic replacements) to 16 MiB, and responses to 8 MiB. Input readers require regular files. Request timeout remains 60 seconds; the runtime drops the request future on cancellation. Existing syntax parsing is skipped for responses of 64 KiB or more.

Endpoint scans check cancellation between entries/files, skip directory symlinks and nested projects, and bound recursion to 64 levels, entries per directory/source files to 10,000, total visited directory entries to 100,000, source files to 1 MiB each, project source reads to 32 MiB, and endpoints to 5,000 per project. The app visits at most 512 projects and retains at most 10,000 endpoints and 1,000 conflict pairs. Reaching a bound produces a partial result. A refresh cancels the previous receiver, and closing the workspace resets both web states so old workspace results cannot appear in the new workspace. Worker disconnects clear progress state.

## Validation

All commands use an isolated target directory, `--locked --offline --jobs 1`, and debug info disabled. Socket tests require loopback binding permission but do not access the internet.

- `cargo test -p rc-app web::tests -- --test-threads=1`: 6 passed. Local servers observe connection closure on both Cancel and Drop, receive the selected environment and actual relative file body, and exercise the response limit. File import verifies parseable output and refusal to overwrite. Cancellation discards stale file-task results. Sending from a different file while the window is hidden clears the previous environment selection before dispatch.
- `cargo test -p rc-app web_window_tests -- --test-threads=1`: 2 passed. Headless egui tests select/refresh environments, click Cancel Request, filter/group conflicts, and explicitly import/open an HTTP file without sending it.
- `cargo test -p rc-dotnet --lib http_file::tests -- --test-threads=1`: 9 passed, including deep/dynamic expansion bounds and existing environment/private/user-file, dynamic-variable, parsing and local-server regressions.
- `cargo test -p rc-dotnet --lib endpoints::tests -- --test-threads=1`: 10 passed, including scanner regressions, method/parameter/constraint conflict cases, cancellation and oversized-source exclusion.
- `cargo test -p rc-dotnet --lib openapi::tests -- --test-threads=1`: 3 passed, covering overrides, encoding, JSON bodies, unsafe/unsupported input and operation bounds.

Locale keys are supplied in `scripts/i18n/batch2-web.tsv` with explicit English fallbacks in all eight supported locale columns. This evidence applies to the listed scopes, not complete Rider parity.
