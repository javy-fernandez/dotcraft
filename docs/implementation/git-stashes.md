# Git stash management

Open the Git tool window and select Stashes. Create a stash with a message, optionally include untracked files or keep staged changes, and apply, pop, or drop existing stashes. Restoring staged changes is optional. Pop and drop require confirmation; Cancel leaves the repository unchanged.

Operations execute asynchronously and refresh the stash list and working-tree status. Modified editor documents are saved first, and worktree-changing actions stop if any document remains modified. Selected stash hashes are checked against a fresh list before using backend indices. Concurrent app Git operations are serialized. The Git window exposes Cancel while an operation is running. Cancellation and workspace closure abort the worker future, dropping its Git child process; the busy state is released after the worker ends. Cancellation does not roll back Git changes already written, so inspect the refreshed repository state before retrying.
